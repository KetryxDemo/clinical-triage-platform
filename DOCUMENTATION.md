# Device documentation set

What a Class II, IEC 62304 Class B, AI-enabled SaMD needs in its design history
file, where each document comes from in this setup, and whether the sample
device has it. "Generated" documents are rendered by Ketryx from items and
builds for every device version; "authored" documents are written once and
controlled in the Ketryx EDMS under *Design History File*.

Regulatory basis: IEC 62304 (software lifecycle, Class B), ISO 14971 (risk),
FDA *Content of Premarket Submissions for Device Software Functions* (Basic
documentation level), FDA AI-enabled device software function guidance
(model, data, performance validation and monitoring elements).

## Not yet covered

- **Quality records** (CAPA, nonconformance, complaint, document control with
  training) are configured under [issue #1](https://github.com/KetryxDemo/clinical-triage-platform/issues/1)
  following the Ketryx eQMS blueprint.
- **Predetermined Change Control Plan**: deliberately out of scope for this
  release; model or prompt changes are full device changes.
- **Clinical performance validation report** with subgroup analysis: the
  urgent-presentation slice is the safety gate, but a broader validation
  dataset and report are still to be produced.
- **Summative usability evaluation** and the full **Instructions for Use**.
